# S1 Core Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tauri 2 desktop app that sets up a programme, builds a full validated day session with `claude -p`, grades it against the rulebook, and derives error bank, re-checks, spelling and progress from the stored answers.

**Architecture:** Pure TypeScript core (`src/core`) behind small ports (`Db`, `Llm`, `ProcessRunner`, `Clock`, `PromptStore`); adapters for Tauri (plugin-sql, plugin-shell, plugin-fs), tests (better-sqlite3, fakes) and browser preview (sql.js, fakes). React UI calls core functions only. Everything derived (schedule, error bank, scores, progress) is recomputed from stored answers.

**Tech Stack:** Tauri 2, React 19, TypeScript (strict), Vite, Tailwind 4 + shadcn/ui, Vitest, Playwright, Ajv, better-sqlite3 (tests), sql.js (preview), Yarn 4 via corepack (`nodeLinker: node-modules`).

**Spec:** `docs/superpowers/specs/2026-10-22-s1-core-loop-design.md` (rev. 2). Read it before any task; section numbers below (§) refer to it.

## Global Constraints

- Core (`src/core/**`) imports nothing from `@tauri-apps/*`, `react`, or adapters. Enforced by an ESLint `no-restricted-imports` rule (Task 1).
- Rust in `src-tauri` only registers plugins; no `#[tauri::command]`.
- Dates are local `YYYY-MM-DD` strings (`ISODate`); never `Date` objects in stored data.
- SQL in migrations: no `RETURNING`, no JSON functions (must run on plugin-sql, better-sqlite3, sql.js).
- Defaults: models `claude-sonnet-5-5` for every kind; `budget_usd` empty; `native_language` `ru`; `spelling_variant` `british`; `accepted_shorthands` `["✓"]`; theme `dark`.
- Timeouts: `generate_session` 300 000 ms; all other kinds 120 000 ms.
- `claude` locations, in this order: `$HOME/.local/bin/claude`, `$HOME/.claude/local/claude`, `/opt/homebrew/bin/claude`, `/usr/local/bin/claude`.
- `claude` call flags (exact order): `-p --output-format json --json-schema <schema> --system-prompt <prompt> --tools "" --model <model> --no-session-persistence --strict-mcp-config [--max-budget-usd <n>] -- <userPrompt>`; the user prompt is the last argument after `--` (`claude -p` waits for stdin EOF; the Tauri shell cannot close stdin). Never `--bare`.
- UI follows `app-design/DESIGN.md` (tokens, two voices, no modals, verdict = icon + word, spellcheck/autocorrect/autocapitalize off on answer inputs, no em dashes in UI strings, no "again"/repeat counts).
- UI strings come from `src/core/i18n` (`ru` default, `en`); task content stays English.
- Commit after each task; messages in imperative mood; never include model identifiers.

## Verified Facts (spike items 1 and 5, run 2026-10-22 with CLI 2.1.308)

- Success envelope: `{"type":"result","subtype":"success","is_error":false,"structured_output":{…},"result":"<json string>","total_cost_usd":0.00077,…}`.
- Budget exceeded: `{"subtype":"error_max_budget_usd","is_error":true,"structured_output":null,"errors":["Reached maximum budget ($0.00001)"],"total_cost_usd":…}`, exit code 0. The cap is checked after the turn, so cost can exceed it.
- `--json-schema` takes inline JSON; multi-line `--system-prompt` works; `--model claude-haiku-5-5` accepted.
- Still to verify on macOS (Task 22): `$HOME` in shell scope `cmd`, multi-line values through arg validators, plugin-sql multi-statement `execute`, not-signed-in envelope.

## Review Focus

1. Spot answers typed with `->`, `=>`, `—>` or extra spaces instead of `→`: the parser must accept all of them (Task 12 test `parseSpotLines accepts arrow variants`).
2. Clicking **Check answers** twice or grading an already graded session: second call must be a no-op returning the stored result (Task 13 test `gradeSession is idempotent on graded session`).
3. A session opened before midnight and graded after: everything uses `session.date`, not `Clock.today()` (Task 13 test `grading uses session date not today`).
4. LLM returns topic keys with different case or spaces (`"Present Perfect "`): keys are normalised (`trim().toLowerCase().replace(/\s+/g,'-')`) before validation (Task 11 test `normaliseTopicKey`).
5. Replacing the programme after sessions exist: topics referenced by items or rules are kept (with `week_no` NULL), never deleted (Task 6 test `replaceProgramme keeps topics referenced by items`).
