# Words (vocabulary practice) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Words page where the learner imports or adds words, the app generates exercises once per word, and the learner practises with cards that move each word through stages on an FSRS schedule.

**Architecture:** Pure logic lives in `src/core/words/`: the parser, checking, replay (stages + FSRS), the queue and card picking. All of it is unit-tested with Vitest. DB access goes in `src/core/db/repos/words.ts`. Two new LLM call kinds (`words`, `word_check`) go through the existing `callStructured`. Progress is replayed from `word_review` rows and never stored (D18). The UI is a Words page, a practice page, a words job provider (modelled on `GenerationProvider`), a line on Today and rows in the error bank.

**Tech Stack:** TypeScript, React 19, Tauri 2 + SQLite, Vitest, Playwright (preview adapter with sql.js), `ts-fsrs@5.4.2` (MIT, new dependency, exact pin).

**Spec:** `docs/superpowers/specs/2026-11-04-words-design.md` (V1–V11). Read it before every task.

## Global Constraints
- UI copy is bilingual: every new string is added to both `src/core/i18n/en.ts` and `src/core/i18n/ru.ts`. Use the exact RU/EN strings from the spec.
- Every interactive element has `cursor: pointer`; disabled ones have `not-allowed` (CLAUDE.md). New pages and states get cases in `tests/e2e/cursor.spec.ts`.
- No modals: panels and forms open inline (DESIGN docs).
- Inputs: `spellCheck={false}`, `autoCorrect="off"`, `autoCapitalize="off"`.
- FSRS: `generatorParameters({ request_retention: 0.9, enable_fuzz: true, enable_short_term: false })`, default weights.
- Constants (in `src/core/words/constants.ts`): `PRACTICE_SIZE = 20`, `NEW_PER_DAY = 10`, `LEARNED_INTERVAL_DAYS = 21`, `CORRECT_DAYS_TO_ADVANCE = 2`, `BATCH_SIZE = 10`.
- Link fallback: `https://www.oxfordlearnersdictionaries.com/search/english/?q=<encodeURIComponent(word)>`. The LLM never produces links.
- Model defaults for the new kinds: `claude-sonnet-5-5`, effort `medium`.
- Checks before each commit: `yarn typecheck`, `yarn lint`, and `yarn test` for the touched test files. E2E tasks also run `yarn e2e <spec>`.

## Review Focus
1. **Pasting text that is not Obsidian cards**, or cards with odd spacing or Windows line endings: the import preview shows 0 cards or named problems. Nothing crashes and nothing is saved. → Task 2 tests `crlf`, `no headings`.
2. **A word whose generation failed or is still pending** must never appear in practice, and it shows Retry in the list. → Task 5 test `skips words without ready exercises`, Task 10 e2e.
3. **Answering the same word twice on one day** (the repeat card, a second practice after Continue, or a second app run on the same day): only the first answer counts for FSRS and the stage. → Task 7 test `second answer same day not counted`.
4. **The lesson job lock is held while words generate** (or the reverse): the words job returns `busy`, the words stay `pending` with Retry, and no exercises are lost. → Task 6 test `busy leaves pending`.
5. **Editing a word's `word` field to one that already exists**, or adding a duplicate by hand: refused with an inline message, not a DB error. → Task 1 repo test `duplicate word case-insensitive`, Task 10 e2e.
